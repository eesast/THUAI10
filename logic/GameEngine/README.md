# 简介

今年一个非常重要的工作是重构游戏引擎，之前的游戏引擎过多依赖多线程的开发方式，这会导致很多性能、逻辑、公平性等问题，目前推荐使用以帧为单位计算的游戏引擎

## 基础内容

新的游戏引擎应该包含以下内容：

- 统一状态：管理实体、地图和游戏时间。
- 指令队列：接收玩家操作，按规则排序、逐帧消费。
- 固定步长：按固定时间间隔更新，移动和冷却使用游戏时间。
- 帧内顺序：执行指令 → 更新行为 → 处理碰撞 → 结算事件 → 创建或销毁实体。
- 状态快照：每帧结束后发布，供通信和显示使用。

要注意游戏引擎的通用性，设计的好的话这个游戏引擎是要年年复用的，推荐这个文件夹下的游戏引擎是个顶层的类，针对 THUAI10 的规则而专门的设计的游戏引擎可以继承这个类。

## 可能的方式

- 单线程更新游戏状态；通信线程只收发指令和快照。
- 累积实际经过时间，每满一个步长执行一帧；不足则等待。
- 落后时补帧，限制单次补帧数，避免持续积压。
- 单次操作只消费一次，持续操作保存为状态。
- 显示可独立刷新并插值，不修改游戏状态。

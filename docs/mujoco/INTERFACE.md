# 选手接口 v1

## 入口

Python `模块名:类名`，构造签名 `__init__(player_id=0, config=None)`，决策函数 `act(observation) -> dict`。两份策略在各自的进程初始化；控制周期中先同时发送观测，再按统一响应期限收集动作。

网页 ZIP 提交固定入口为 `policy:Policy`，两名选手在独立的 Linux 容器内初始化，使用受限 JSON / 数组传输保持下述观测与动作结构。统一环境、上传步骤及限额见 [WEB_PLATFORM.md](WEB_PLATFORM.md)。原生 CLI 仍允许指定其他模块与类。

构造函数的公开配置不包含本局布局随机种子。裁判侧保留种子、真实藏点和动态角色状态；固定练习环境的默认种子可以用于本地复现，正式隐藏评测需要组织者另行设定。

## 输入

| 字段 | 内容 |
| --- | --- |
| `schema_version` | 当前为 1 |
| `time` | 仿真时间，秒 |
| `player` | 0 或 1 |
| `reset_count` | 本选手累计物理复位次数，发生变化时策略应重置运控历史 |
| `proprio.joint_names` | 29 个关节名及排列顺序 |
| `proprio.q` / `dq` | 关节角度 rad / 角速度 rad/s |
| `proprio.base_quat` | 基座姿态四元数，顺序 w,x,y,z |
| `proprio.gyro` | 自由基座本体坐标中的角速度 rad/s |
| `proprio.foot_contacts` | 左、右脚接触数量；当前为接触指示，不是高分辨率触觉阵列 |
| `visual.rgb` | uint8，H×W×3，RGB 顺序 |
| `visual.depth` | float，H×W，米；沿相机光轴的深度，不是沿像素射线的斜距 |
| `visual.time` | 该帧采样的仿真时间。图像比动作更新慢，允许重复帧 |
| `visual.fovy_degrees` | 垂直视场角 |
| `tasks` | 当前公共任务和自己的个人任务，每项含 id、kind、text、reference_rgb |
| `game` | 自己的 health、score、alive、stun_remaining、cooldown_remaining、remaining |

当前参考图为独立生成的杯子示意图，未泄露其场景位置。RGB-D 观测不返回物体真值坐标、物体分割标签、对方个人任务或对方内部状态。自己的姿态、本体几何及关节状态允许用于建立自身运动学模型。

城市中的悬浮车、巡逻机器人、机器狗和无人机出现在真实 RGB-D 观测中，不单独向选手发送其世界坐标或速度。任务文字会指明目标所属场所；选手需要自行识别环境、搜索并控制行动。车辆接触惩罚反映在自己的生命值中。

相机位于躯干前上方，本体坐标中的具体位置与朝向由公开场景构建代码定义；当前没有独立头部转动关节。图像坐标原点在左上，x 向右、y 向下；MuJoCo 相机局部坐标前方为 -Z，上方为 +Y。

## 输出

```python
{"joint_targets": numpy_array_of_shape_29, "fire": False}
```

关节目标必须是有限实数，并按 `joint_names` 排列；超出关节范围时统一限幅。`fire` 必须为布尔值。错误形状、NaN、缺失字段等会记录 `invalid_action`，保留上一有效关节目标且本周期不生成射击。

`fire=True` 只是请求。在死亡、开火冷却或被禁火期间，请求被拒绝，不生成射击事件，也不按射击失误扣血。

当前仿真采用固定动作周期 0.02 秒，图像每 0.10 秒更新一次。较慢的视觉模型应在策略内部缓存结果，由较快的运控循环继续生成关节目标。策略必须自行考虑倒地后的起身，平台只在超时后强制复位。

## 机器人匹配、关节重排与编译

网页清单可声明 `robot_id=unitree_g1_29dof`、`control_mode=joint_position`、`joint_unit=rad`。旧模板省略时按当前统一 G1 接口处理，明确不匹配的声明会被拒绝。

默认输出按观测 `joint_names` 排列；如果清单包含 `action_joint_names`，它必须是完整的 29 个唯一 G1 关节名称，平台将模型输出按名称重排。状态预处理、归一化动作还原和控制器适配由选手负责，不自动补齐其他本体的关节。

初始化前在隔离容器内编译包内全部 `.py` 文件，再导入 `Policy` 并调用动作；编译错误提供相对文件名和行号。该步骤不包含 C/C++ 源码编译，也不代替实际运控能力验收。详见 [参赛适配指南](SUBMISSION_GUIDE.md)。

## 运行异常

- 初始化失败：整局启动失败，显示具体错误。
- 单次推理超时：本周期沿用上次关节目标，不开火；过期返回值丢弃，避免套用到新的观测周期。
- 策略异常：记录错误，不停止另一份策略。
- 策略进程退出：记录退出事件，该选手保持最近关节目标；原型不会自动判负，仍按任务分结束比赛。

原生 CLI 的本地受信运行器仍采用 Python 进程通信，不作为陌生代码边界。网页运行器采用独立容器与受限消息协议，不回退到该受信运行器。已验证的局域网功能和待完成的公网 / GPU 能力见 [STATUS.md](STATUS.md)。

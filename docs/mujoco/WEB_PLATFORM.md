# 选手平台使用说明

## 启动

在仓库根目录运行 `dependency/shell/mujoco/start.cmd`，在本机打开 <http://127.0.0.1:8767>。

新机器首次安装运行 `dependency/shell/mujoco/deploy.cmd`：创建 Python 环境、安装固定依赖、下载并校验本体资源、准备策略环境、完成真实仿真通信自检，再启动网页。使用 Python 3.13，并提前安装 Docker Desktop Linux 引擎。

启动器会等待服务真正就绪，再打开浏览器；平台独立在后台运行，关闭启动窗口不会停服。重复运行会打开已有平台，不重复启动。电脑重启后仍需先运行启动器，目前未设置开机自启。后台日志保存在 `logic/mujoco/var/platform/service.out.log` 和 `service.err.log`。

第一次打开由你设置管理员账号与密码，没有预置账号或默认密码。创建管理员只允许从服务器本机访问；其他设备不能抢先初始化。账号需要 3–24 位字母、数字或下划线，密码需要 10–128 个字符。

`start.cmd` 默认监听局域网。其他设备使用这台机器的局域网 IP 加 `:8767` 访问；系统防火墙需要允许该服务的局域网连接。现有 .NET 启动器配置默认只监听本机。自定义域名需通过 `ARENA_ALLOWED_HOSTS` 添加允许的主机名。公网部署需要另行配置 HTTPS、代理、访问控制和容量验收。

仅准备 Python 与资源、不启动网页时，在仓库根目录执行：

```powershell
.\dependency\shell\mujoco\setup.cmd
```

资源保存在 `logic/mujoco/third_party/`，世界资源和配置也在 `logic/mujoco/`。程序按仓库分工访问界面、CAPI 和依赖目录，请保留完整目录结构。分发包与 .NET 启动器的初始化见 [启动器接入](../../installer/mujoco/README.md)。

## 管理员先做什么

1. 到“比赛管理 → 运行环境”检查执行节点。
2. 到“运行环境”点击“一键部署并自检”。平台会检查资源、启动已经安装的 Docker Linux 引擎、复用或准备统一镜像，并验证两份策略与真实 MuJoCo 的 RGB-D／关节动作通信。部署期间队列保留，当前有运行场次时会提示等待结束。也可在仓库根目录执行 `dependency/shell/mujoco/configure-runtime.cmd`。
3. 到“邀请码”生成邀请码，设置有效期和可使用次数。完整码只返回一次，数据库保存摘要；请复制给参赛者。
4. 在“选手账号”查看账号或启停账号。停用会立即撤销该账号的登录会话。
5. 等两名选手完成接口检查并报名，再在“队列与排赛”中安排正式比赛。
6. 正式场次完成后检查真实结果和回放，点击发布。发布前仅参与者与管理员可见，发布后平台内选手可见。

解锁报名只允许选手重新选择之后的参赛版本，不会改动已安排场次绑定的版本。暂停练习只暂停接收新练习，不中断正在运行的局。

## 选手如何提交

1. 使用邀请码注册并登录，点击“下载参赛模板”。
2. 保留 `submission.json`、`policy.py`；离线模型放 `models/`，辅助模块放 `src/`。
3. 实现 `Policy(player_id=0, config=None)` 与 `act(observation)`。使用 `Path(__file__).resolve().parent` 拼接包内路径。
4. 填写策略名称、可选说明，选择 ZIP，点击“上传并检查”。页面显示真实传输进度。
5. 上传后生成不可覆盖的 V001、V002 等版本。自动解压并检查 ZIP、清单、机器人、单位和入口语法；静态阶段不导入代码。
6. 隔离阶段编译包内全部 Python 文件，再在两个实例中实际导入和初始化策略，连续三次检查 RGB-D 观测下的动作。错误报告提供相对文件名与行号。通过只说明接口有效，不说明能站立或找到目标。
7. 在“练习中心”选择已通过检查的版本。默认同版本两个独立实例，也可用自己的历史版本对战。可选择城市或房间场景。
8. 在“正式比赛”选择并锁定报名版本。后续上传不会自动替换报名。

上传时可勾选“检查通过后自动开始城市练习，并返回成绩与回放”。运行检查通过后自动进入练习队列；管理员暂停接收练习或本人已有两场未完成练习时，会提示手动发起。练习结果从“练习中心”查看。练习是评测，不优化模型参数、不生成新权重。

运行检查失败可以重新检查同一版本；静态错误、源码修复或权重替换需要上传新版本。详细的机器人适配、完整清单与关节重排说明随下载模板附带，另见 [SUBMISSION_GUIDE.md](SUBMISSION_GUIDE.md)。

动作接口与规则见 [INTERFACE.md](INTERFACE.md)。原本地受信 CLI 继续保留；网页上传代码只走隔离执行器，不使用原 Python 进程运行器。

## 运行环境与限制

当前开放 `arena-python-v1`：Python 3.13、NumPy 2.5.5、Pillow 13.0.0、ONNX Runtime 1.32.0，提供 CPU 推理。Torch、OpenCV、CUDA 等没有被默认安装。额外依赖可在“接口与环境”提交申请，管理员回复并不自动安装或发布环境。

第一次连接的镜像摘要会固定；同名环境若换成另一摘要，平台拒绝继续执行，避免历史结果使用不同依赖。保留原镜像，不要在已使用的环境名下更新依赖。管理员可构建、验证并发布预定义的 PyTorch CPU 或 CUDA 环境，配方和限制见 [运行环境](../../dependency/docker/mujoco/README.md)。依赖申请继续用于收集意见。

每名选手策略使用独立 Linux 容器：非 root、只读提交、只读系统、无外网、私有临时目录、删除全部额外 capabilities、禁止新增权限、CPU / 内存 / 进程上限。仅挂载自己的提交；不挂载网站、裁判世界、数据库、Docker 套接字或其他选手代码。动作与观测通过有大小、深度与数组类型限制的 JSON 协议传输，没有跨边界 pickle。

默认上限：

| 项目 | 默认值 |
| --- | --- |
| ZIP / 解压后 | 128 / 512 MB |
| 账号提交存储 / 版本数 | 1024 MB / 100 个版本 |
| 每名策略 CPU / 内存 / 进程数 | 1 核 / 1024 MB / 64 |
| 私有临时目录 | 128 MB |
| 初始化 / 单次动作响应 | 90 / 1 秒 |
| 每局实际时间上限 | 900 秒 |
| 练习时长 / 并行局数 | 60 仿真秒 / 1 局 |
| 每人未完成练习 | 2 局 |

平台分别显示仿真进度与实际用时，当前城市没有实时速度保证。初始化不联网下载权重。超时、异常、无效动作沿用现有裁判规则，不额外引入判负规则。执行节点未就绪时可保存上传与静态检查，运行检查和比赛保持等待，禁止回退到宿主机直接运行。

Docker 提供基础运行隔离，本轮验证不等于完成恶意容器逃逸审计或公网生产验收。当前适用于管理员控制的局域网试赛；正式开放报名之前还需针对目标硬件进行持续负载、漏洞和恢复验收。

## 回放、日志与复现

网页回放来自本局 MuJoCo 的真实画面，包含第三人称与双方 RGB 摄像头，支持播放、暂停和时间轴。当前网页录像为 2 Hz；完整 50 Hz 状态与动作轨迹仍保存在服务器。

练习及其图片接口仅本人和管理员可读。正式比赛经发布后提供画面、成绩和允许公开的事件。源代码、模型包及策略日志仍受单独权限控制；一个参赛者也不能查看对手的私有错误消息。页面退出会移除缓存的私有内容。

管理员的完整复现清单保留提交 SHA-256、环境镜像摘要、场景配置和随机种子；选手下载的清单隐藏布局种子。每局还保存现有 `scene.xml`、`trajectory.npz`、环境与资产记录。跨硬件逐位一致性没有保证。

## 数据与维护

- 正式数据默认在 `logic/mujoco/var/platform/`，包括数据库、ZIP、解压后的提交与比赛记录，全部在网页静态目录外。
- 可用 `ARENA_DATA` 指向独立的数据盘；不要从静态 Web 服务直接暴露该目录。
- 当前单进程、单仿真队列。服务对数据目录加进程锁，避免重复启动或多 Web worker 同时运行。
- 重启后，中断的运行保留失败记录；等待队列继续处理。只清理本平台安装标记的残留策略容器。
- 本轮自动验收与测试账号放在 `logic/mujoco/artifacts/platform_validation/`，不写入正式账号库。
- 对外发布前配置 HTTPS 时设置 `ARENA_HTTPS=1`，并通过可信反向代理服务。当前启动器不自动修改系统防火墙或对公网发布。

基础镜像采用 [Docker 官方 Python 镜像在 ECR Public 的发布](https://gallery.ecr.aws/docker/library/python)，当前默认源避开本机无法连接的 Docker Hub 认证地址。资源限制依据 [Docker 官方容器资源文档](https://docs.docker.com/engine/containers/resource_constraints/)。


## v0.4 赛事与维护

「赛事与总榜」生成固定版本、多布局、出生位置与私人任务组互换的循环赛，全部完成后统一发布积分榜。失败场次可按原配置重试。

「后台维护」每天备份数据库和原始提交 ZIP，保留最近七份完整快照；过期三十天的练习文件可自动清理，保留成绩，正式比赛文件保留。站内告警报告磁盘不足、维护异常与运行失败。快照不包含回放；恢复只写入全新目录，撤销旧会话，并把未备份的历史回放标记为不可用。从仓库根目录运行：

```powershell
.\logic\mujoco\.venv\Scripts\python.exe dependency/shell/mujoco/restore_platform.py <完整快照目录> <全新数据目录>
```

「运行诊断」显示自己策略的响应耗时、生命曲线及裁判事件计数；练习中心提供两次运行对比。服务重启会使用原版本、种子与出生配置重跑中断场次，最多自动恢复两次，并非从中间物理状态续跑。
